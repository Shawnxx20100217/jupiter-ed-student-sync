# 共享版本安全检查记录

这是发布前检查清单和证据范围说明，不是对所有未来版本的安全保证。当前仓库保持 Private；公开需要维护者明确确认。独立测试账号首次真实登录尚未验证，不能用私人生产数据代替这一验收。

## 已采用的隔离边界

- 独立目录、独立新 Git 历史；不 Fork 私人生产历史，不导入其状态分支。
- 只允许通用代码、示例配置、人工合成测试和文档进入模板。
- 真实账号、学校配置、课程作业成绩、浏览器会话、Token、密钥、任务 ID 映射、验收回执及部署标识不得进入模板。
- 无凭证安全失败；没有私人账号或状态回退路径。
- 状态绑定当前仓库和账号/学校/学年/学期范围；状态存在时拒绝首次初始化覆盖。
- 第一版不包含 TickTick 写入客户端或 Jupiter Done、提交、上传入口。
- 日志只提供状态码、计数和必要健康信息；明文导出只保存在本地私有目录。

## 可重复执行的扫描

```sh
npm run audit:shareable
```

该检查扫描分享目录和本地所有 Git blob/commit 对象，包括已删除文件及不可达对象。规则覆盖常见 Token、私钥、浏览器状态、明文凭证赋值、个人本机路径、私有数据文件、复制来的生产写入入口和危险工作流配置。

在首次提交之前可以运行 `node scripts/audit-shareable.cjs --source-only`，但此模式**不等于历史审核通过**。首次提交后必须运行完整检查。合成 CI 只检出当前源代码提交，不下载学生初始化后的私有状态分支，因此 CI 的扫描只覆盖这次检出的源文件和本地对象，**不代替维护者发布前的完整历史审核**。

维护者还应准备放在仓库外的私有排除清单，包含原私人项目的姓名、账号、仓库、学校配置、任务 ID、来源指纹、部署标识等已知值，然后运行：

```sh
node scripts/audit-shareable.cjs --deny-file /outside/repository/private-denylist.json
```

清单格式是 JSON 字符串数组。扫描器不打印匹配内容，也拒绝仓库内部的排除清单。排除清单本身不能提交。它只能发现已知字符串及规则覆盖的模式，不能证明不存在所有未知敏感信息；仍需人工检查文件清单、依赖、网络目的地和 Git 历史。

`node_modules`、`dist`、`.private`、`.cache` 不作为可分享源目录扫描；若它们已进入 Git 对象，历史扫描仍会检查。运行时密文、导出、截图、日志不能加入模板。

## 测试证据如何解读

| 项目 | 验证方式与限制 |
| --- | --- |
| 敏感内容检测 | 人工构造 Token、已删除历史、不可达对象；报告必须不回显样本内容 |
| 新用户隔离 | 人工构造两个账号/仓库/密钥及错误身份，验证不交叉恢复 |
| 首次初始化 | 合成空状态与已有状态，验证必须明确初始化且已有数据不能覆盖 |
| 加密与失败保护 | 合成篡改、错误密钥、并发冲突和保存/回读失败场景 |
| 读取与日期 | 人工构造正常/维护/异常页面及日期证据，不使用真实学生快照 |
| 全新 Ubuntu 环境 | CI 包含真实无头浏览器启动，但只加载合成页面，不登录 Jupiter；结果以实际运行记录为准。CI 只检出源码当前提交，不代替真实账户读取或完整远端历史审核 |
| 独立账号首次真实读取 | **未验证**：需要账号拥有者明确授权及正常登录条件 |
| 对外公开 | **未授权**：完成以上检查后再请求确认 |

本文件不硬编码一次测试数量或临时 CI URL；最终测试与扫描结果应从对应提交的 CI 以及本地扫描输出核实。禁止把手工编写的本表当作已执行的证据。

## 存储和协作者风险

私有仓库的 `sync-state` 分支保存认证加密的数据封装，以及仅含 schema、最近成功采集时间、序列号、验证标志的 `health.json`；学业明文不进入该分支。仓库读者仍可看到密文大小、更新时间和提交元数据。持有正确密钥与账号范围配置者可以解密；有工作流编辑权限的人也可能通过恶意代码取出 Secrets，因此不要邀请无关协作者，不要自动运行陌生改动，不要公开状态分支。

导出后的 JSON 是明文学业数据。`.gitignore`、文件夹名或私有仓库并不能替代谨慎分享。不要将该文件上传到公开 Issue、CI artifact 或第三方网站。

## 公开前必须确认

1. 对最终提交运行源码、所有 Git 对象及外部私有清单扫描，检查结果没有未解决发现。
2. 人工检查新仓库只有通用文件和新历史，且生产仓库、Secrets、状态分支均未被修改或共享。
3. 确认 MIT 许可与上游署名保留，依赖许可证未被移除。
4. 由独立测试账号完成首次初始化和自己的数据核验；失败或未测必须保持明确标记。
5. 得到维护者对**这个独立模板仓库**公开的明确批准；该批准不涵盖任何学生部署仓库。
